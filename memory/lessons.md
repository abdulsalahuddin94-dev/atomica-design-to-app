# Lessons (mistakes fixed, so they never happen again)

Every mistake Abdul reports or a check finds gets one entry here in the session that fixes it: what broke, the root cause, the rule now in the workflow, and the check that catches it. Read before building or updating anything of the same kind. Newest first.

Teammates share their lessons through `/contribute` (`CONTRIBUTING.md`); an entry lands here only after Abdul accepts it, marked `(contributed by <login>)`.

## The Root stayed on a merged thread branch, so the dashboard could not update (2026-11-11)
1. **"Update now" and `git pull --ff-only origin master` failed with "diverging branches" (Abdul).** The Root was still on a thread branch whose pull request had been merged two days earlier. On top of it sat one local, never-pushed commit that merged master into the branch; master later got the same work through a different merge, so the two histories split although nothing was really missing. Three edits from an earlier session were also left uncommitted in the Root.
   Cause: a thread session that works directly in the Root (Remote Control, no worktree) switched the Root to its branch and never switched back after its PR merged; the dashboard refused any branch other than master and gave no way out. Rule: a session that checks out a branch in the Root returns the Root to master (fast-forwarded) when its work is pushed, and commits or hands over any edits it leaves there. A Root on a branch whose commits are all in master (only merges of master into it) is safe to leave: keep its tip as `backup/<branch>-<date>`, switch to master, fast-forward; uncommitted edits move along with the switch. A branch or local master with real unmerged commits is never switched or reset without the user. Check: `dashboard/workflow-update.mjs` does this on "Update now"; `node --test tools/tests/workflow_update.test.mjs` covers the merged branch, an open branch and a local master with its own commits.
2. **Right after that, Update now stopped again on `memory/lessons.md` (Abdul).** Another running session had added two lessons there without committing, and the update also added a lesson at the same place, so the fast-forward refused.
   Cause: sessions add lessons in the Root and commit them later, and every lesson goes to the top of the same file. Rule: Update now sets local edits in files the update touches aside in a named stash, updates, then puts them back; `memory/lessons.md` merges with `merge=union` (`.gitattributes`), so two new lessons at the top are both kept with no conflict markers; an edit that still cannot go back leaves the updated file and stays in the stash, named in the message. Check: the union and kept-in-stash tests in `tools/tests/workflow_update.test.mjs`.

## A failed FigCli write script is not rolled back (2026-11-08)
1. **A script that threw left a half-built screen and a clone behind.** The Assigned tasks build failed on a missing variable and the Trips script failed at its menu step; the new frames stayed on the page, although the Plugin API rules say a thrown error rolls the call back.
   Cause: under FigCli eval, edits made before the throw stayed. Rule: after any failed FigCli write, list what the script creates and remove only those copies before re-running; guard scripts with an "exists" check. Check: the guard throws on re-run when a leftover exists.

## Placing a photo: instance avatars and plugin data (2026-11-03)
1. **`place_image.cjs` refused the Profile Avatar and then failed on every node.** The avatar is an Avatar instance whose image is the instance's own fill, and the tool only accepted frames and rectangles; after that was fixed, `setPluginData` threw "Cannot set private plugin data in a plugin without an ID" under FigCli eval and rolled the whole write back.
   Rule: image fills may go on an instance's own fill (an override); FigCli eval has no plugin id, so store data with `setSharedPluginData('aiready', ...)` inside a try. Check: the script's result shows `fill: IMAGE` and `credited: true`, then a `verify` screenshot of the screen.

## Screens did not match the running source; frames under 900 high (2026-11-03)
1. **Each code-to-Figma sync left color, shape and size differences (Abdul).** Abdul had to send screenshots after every build to point them out.
   Cause: the comparison was a screenshot next to the source, judged by eye at reduced scale; 12 vs 14 px text, 500 vs 600 weight, 16 vs 20 radius and line-height drift do not show at that scale, and values with no exact variable were snapped to the nearest one without saying so. The first measured run on one profile screen found 71 differences the eye check had passed. Rule: measured fidelity (screens.md 7f step 4b): dump the running source and the Figma frame, run `tools/fidelity_diff.py`, fix until Open differences is 0 or explained; list unmatched exact values for approval. Check: no screen is reported without its `audits/<date>-fidelity-<screen>.md`.
2. **Desktop screens were 1440 x 776 and 1440 x 880.** Cause: the screen-fitting helper used in the build scripts hugged the content with an 880 minimum instead of the 900 floor, and older screens were never re-checked. Rule: helpers take the floor from section 7d (Desktop height at least 900, Mobile 375 x 812); after any re-layout run `tools/check_screens.figma.js` (`frameSize`). Check: ds-auditor screens mode reports every frame under the floor.

## Moving nodes between instance slots (2026-11-02)
1. **Cells moved from one slot to another could not be read or edited by scripts afterwards.** In the Requests table, shifting slot contents one column right (to make room for Task) rendered correctly, but every moved node threw "node does not exist" on read, so styling them later failed.
   Rule: to change a slot's content, build or clone new nodes into the target slot and remove the old ones; never move existing slot children between slots of an instance. Check: read the target slot's children right after the change; any read error means the content was moved.
2. **Resize and sizing overrides on cells inside an instance are ignored.** Header cells could not be resized to match a different row component. Rule: pair components that share the same cell sizing (Table Header Row with Table Row / Table Row Custom, all cells fill) instead of resizing nested cells.

## Re-laying out a screen grid deleted a card (2026-11-02)
1. **The Empty State Overview lost its Project Health card.** The script picked cards by layer name; two instances were both named "Project Health" (the status card and the Stage Gates empty card), so one was moved twice and the real status card stayed in the old column, which the script then removed.
   Rule: when moving children into a new layout, pick nodes by main component (set + variant) or id, never by layer name alone, and remove an old container only when it is empty (`children.length === 0`). Check: count the instances in the grid before and after the move; the counts must match.

## FigCli writes: fonts, tints and file target (2026-11-01)
1. **A write script hung until the 60 s FigCli timeout and changed nothing.** It created text nodes without loading Inter, the default font of `figma.createText()`; the same happened when setting `textAlignHorizontal` on a text whose font was not loaded.
   Cause: an unloaded-font write does not throw through FigCli eval, it stalls. Rule: every script that creates text loads Inter Regular plus each target font first, and any text property write (alignment, characters, decoration) loads that node's font. Check: wrap write scripts in try/catch and time the first run; a timeout with no error means a missing font load.
2. **10% / 30% fills went back to 100% after a Light-mode screenshot.** Paint opacity on a variable-bound paint was reset to 1 when `setExplicitVariableModeForCollection` was called on the node or an ancestor (it also reset an older 70% text in the Project Card, restored from the saved version through the REST API).
   Rule: transparent tints of a token are separate layers ("Tint Fill" / "Tint Border", absolute, stretch) whose layer opacity carries the alpha, never paint opacity on a bound paint. Light screenshots are taken from a temporary frame of instances with the mode pinned there, then deleted; never pin modes on the original. Check: after any mode pin, re-read paint opacities of bound paints.
3. **A FigCli command with FIGMA_FILE set ran on the other open file.** A stale elevated daemon answered some commands for another open file while FIGMA_FILE named the DS file.
   Rule: every write script starts with `if (figma.fileKey !== '<key>') return` before any change. Check: the first line of the script result names the file.
4. **Screenshots looked solid because the PNG alpha was dropped when combining images.** Rule: composite exports with alpha onto the mode background (dark surface or white) before judging colors.

## Sync to Figma from the prototype (2026-11-01)
1. **A slot waited on the Desktop Bridge although FigCli could make it (found while syncing).** The Bridge plugin had connected to another figma-console instance (port 9223, another session), so this session's server saw no file.
   Cause: `decisions.md` says `figma.createSlot` is missing in FigCli; in this Figma build `COMPONENT.createSlot()` exists in FigCli eval too. Rule: before asking for the Bridge, check `typeof variant.createSlot` through FigCli; on a set, call it per variant, then point the extra variants' slot at the first property (`slot.componentPropertyReferences = {slotContentId}`) and `deleteComponentProperty` the duplicate. Check: `componentPropertyDefinitions` lists one SLOT property. Bridge "no files connected" with `otherInstances` in `figma_get_status` = close and reopen the plugin.
2. **A boolean that the prototype uses to change padding (Top App Bar Show Navigation) cannot be a Figma boolean.** Rule: when a code-first prop changes padding, gap or size, build it as a variant True / False (Abdul's choice) and keep the code prop boolean. Before converting a component used in Design files into a set, snapshot every instance's texts and booleans, compare after Accept updates (`combineAsVariants` re-keys the properties; here all 10 titles survived).
3. **Profile came out 12 px shorter per header than the prototype.** A Section Header with Show More off hugs to 24 in the DS, but the prototype generator hides the More layer and keeps 36. Check: when a fidelity diff shifts at a section, compare that header's height in Figma and in the generated screen before changing either.
4. **Pulling a screen whose content sits in a SLOT lost that content (found by a check).** The Share Sheet came back as the Sheet's default text and no links. Cause: `tools/screens_export.figma.js` reads an instance as a leaf with overrides, so slot children are never exported. Rule: until the exporter and generator read slots, a screen built in a slot stays code-first: leave its frames out of the pull and give its `add_screen` override the Figma frame ids so links resolve. Check: after a pull, grep each generated screen for the links its Figma frame has (e.g. `back()` count).
5. **`screens_export.cjs` crashed at the crop step and `--reuse` then used the old crops.json.** Cause: the crop eval awaits once per image layer, and in a background tab each await is slowed to about 30 s (lesson 2026-10-13). Rule: check `document.visibilityState` before a pull; if `hidden`, ask for the tab first, or compute only the missing crops in one script that walks the loaded page synchronously. Check: every image layer id in screens.json has a crops.json entry.

## Live prototype publishing from the dashboard (2026-10-28)
1. **Publish stopped with "the repo does not exist" (Abdul).** The repo existed; publishing from a terminal worked.
   Cause: `tools/publish_prototype.cjs` checked the repo with `gh repo view` and read any failure as "missing"; the dashboard Abdul had started ran where `gh` was not signed in. Rule: the repo is checked with git (`git ls-remote`, no sign-in for a public repo); only a real not-found counts as missing, and without a signed-in gh a not-found is "missing or private"; auth, network and missing-tool errors keep their own message and fix. gh is optional (only to create a repo or turn Pages on). Every publish runs the preflight `tools/publish_checks.cjs` first (packages, Git, repo, write access with a dry-run push, Pages, gh) and prints each problem with its fix; the dashboard shows the same list in the Publish panel and in Connect services (Check publish setup), and starts its child processes with the user's full environment (`userEnv()`). A new repo is created only after the user's click (Create the repo and publish). Check: `node --test tools/tests/publish_dashboard.test.mjs` (auth is not not-found, missing repo, gh signed out) and `node tools/publish_prototype.cjs <project> --repo <owner/name> --check`.
2. **Publish changes stayed disabled after edits (Abdul).** Cause: the Design page read the publish state once, when it opened, and only compared `routes.tsx` with the last publish; Claude's edits while the page was open were not seen. Rule: opening the Publish panel reads the state again; unpublished changes compare the newest file the build uses (`src`, `data`, `public`); the button always works ("Publish again"); a failure shows in red with its reason. Check: the change-detection test in the same file.
3. **The live prototype showed as a second Storybook chip (Abdul).** Cause: every GitHub Pages link was labelled Storybook. Rule: links come from the project's config first (`status.json > prototype.url`, `storybook_url`, `figma`; the last publish), then names (`storybook` / `design-system` = Storybook, anything else a plain site link). Check: the links tests with a second, invented project.

## New library instances looked Light inside Dark screens (2026-10-20)
1. **Fields created with `createInstance()` from an imported shared-library component rendered white in a dark dialog.** Cloned fields next to them were dark.
   Cause: the library main component carries an explicit Semantic mode, and a fresh instance copies it, so it ignores the frame's mode. Clones of existing instances do not have it. Rule: after `importComponentByKeyAsync(...).createInstance()`, clear `explicitVariableModes` on the new instance (`clearExplicitVariableModeForCollection`) unless the design wants that mode. 2. **A failed clone left a stray node on the page.** `node.clone()` of a node from another page lands on the current page; the script failed before `insertChild`, so the copy stayed at (0,0). Rule: after any failed write script that clones, list the page's top-level children and remove only the copies that script made.

## Heavy audit reads froze a Figma tab (2026-10-20)
1. **A ds-auditor read froze a large Code to Design screens file.** A screens audit ran `findAll` over whole screen frames with a nested `findAll` per text node; FigCli timed out at 100 s, the script kept running inside Figma and every later eval on that file failed (even `1+1`) until the tab was reopened. ## Dashboard terminal buttons on Windows (2026-10-15)
1. **Sign in opened an empty terminal (Abdul).** Settings → Gemini CLI → Sign in showed "The filename, directory name, or volume label syntax is incorrect" and never started `gemini`; every button that opens a terminal (Sign in, Open, Continue with another tool, phone, Open in Claude Code) had the same bug.
   Cause: `runInTerminal` passed `cd /d "<Root>" && <cmd>` as a spawn argument; Node escapes its quotes as `\"`, which cmd.exe does not understand, so the `cd` failed and `&&` skipped the tool. The tests only checked the command strings, never a launched window. Rule: on Windows, start the window with one verbatim command line (`cmd /d /s /c "start "" cmd.exe /k <cmd>"`, `windowsVerbatimArguments`) and the Root as `cwd`, so no `cd` is needed. Check: launch one terminal button for real (a script that writes `cd` and its quoted argument to a file) before calling the change done.

## Size tokens bound on resizable components (2026-10-13)
1. **The Play button turned into a pill (Abdul).** After `md/sys/size/touch_target` (48) was bound to the height of every Icon Button and Button variant, the Play button in Playback Controls (resized to 64 x 64) became 64 x 48, the Mini Player Play (40 x 40) became 40 x 48, and the Section Header More button grew from 36 to 48.
   Cause: a variable bound to a main component's height wins over the height of every resized instance, so each instance that had been scaled kept its width and snapped to the bound height. ## Reorganizing screens in a Design file (2026-10-13)
1. **Dark screens turned Light after the file was reorganized.** Moving the Dark and Light screen frames out of their old sections into one section per screen dropped the Dark look.
   Cause: the Light/Dark mode was pinned on the old SECTION (`explicitVariableModes`), not on the frames; a frame takes its mode from its parent, so moving it changed its colors without any error. ## FigCli Yolo writes in a background tab (2026-10-13)
1. **A docs-page build hung and left duplicates.** Building ➜ Color through FigCli `eval` stopped after a few nodes; the CLI timed out, retried on its sync path, and the stalled scripts kept adding nodes about every 30 s.
   Cause: the DS file was not the visible Figma tab (`document.visibilityState` = `hidden`), so every async Plugin API call (`setTextStyleIdAsync`, `loadFontAsync`) was throttled to about 30 s. Reads and sync calls stay fast, which hides it. A timed-out `eval` keeps running inside Figma. After a timeout, remove the half-built container so the stalled script fails on its next write, then rebuild. Check: one `eval "document.visibilityState"` before the first write of each batch.

## Hooks on a new machine (2026-10-07)
3. **Node.js still had to be installed by hand.** The setup check runs on Node.js, so a machine without it got no offer at all; Abdul wants a non-technical user to install nothing by hand.
   Rule: `Setup-Windows.cmd` / `Setup-Mac.command` in the Root install every item of `tools/dependencies.json` with one double-click (winget / Homebrew; download pages when winget is missing). Inside Claude, a session start with no hook context means the hooks did not run: Claude checks `node --version` and installs Node.js itself after the yes (CLAUDE.md > Always start here, `steps/machine-setup.md`). Check: run `tools/setup_windows.ps1` with a tool missing: it is installed or its page opens; a new dependency needs only a `dependencies.json` entry on Windows, and the same line in `Setup-Mac.command`.
2. **Dependencies were found one by one, by failing.** Python was only discovered missing when a hook broke; nothing listed what a new machine needs or checked it, and Abdul did not want a check costing time every session.
   Rule: one list, `tools/dependencies.json` (Node.js, Python 3, Git, Figma Desktop, with per-OS install commands). The SessionStart hook `setup_check.cjs` checks it, records success once per machine in `.claude/.state/machine-setup.json` and skips the checks after that; anything missing -> `Design_System_Intake_Skill/steps/machine-setup.md` offers one "Set up now" menu, installs after the yes, then a restart. Hook commands use `node -e ... run.cjs <hook>` (no `$CLAUDE_PROJECT_DIR` shell syntax), because Claude Code on Windows runs hooks in PowerShell when Git is missing. Check: `node .claude/hooks/run.cjs setup_check --report`; a new tool the workflow needs goes into `dependencies.json`, never only into a skill.
1. **"Stop hook error: Python was not found" on a colleague's first run (Windows).** Every hook in `.claude/settings.json` ran `python ...`; on Windows without Python, `python` is the Microsoft Store alias, which only prints an install message and fails, so every Stop, Edit and Figma call showed a hook error.
