# Lessons (mistakes fixed, so they never happen again)

Every mistake Abdul reports or a check finds gets one entry here in the session that fixes it: what broke, the root cause, the rule now in the workflow, and the check that catches it. Read before building or updating anything of the same kind. Newest first.

Teammates share their lessons through `/contribute` (`CONTRIBUTING.md`); an entry lands here only after Abdul accepts it, marked `(contributed by <login>)`.

## Drawer built from code text instead of the source look (2026-10-20)
1. **The Meetings drawer did not match the repo screenshot (Abdul).** Section titles were UPPERCASE (copied from the code's `label-eyebrow` CSS and the old KPI labels), attendee and action rows had no frame, and there was no drawer showing actions.
   Cause: the drawer was assembled from the code classes and a reused Clients & Vendors drawer, without a screenshot of the running source to compare. Rule: uppercase text was not allowed in that project's screens (Abdul); write labels in sentence case even when the code uses `uppercase`. List rows that the source draws with a border get a framed row (field background, border and radius copied from the DS input). Every drawer or popup variant that shows content in the source (e.g. a drawer with actions) gets its own frame. Check: capture the source screen before building and compare side by side; scan the page for all-caps text.

## New library instances looked Light inside Dark screens (2026-10-20)
1. **Fields created with `createInstance()` from an imported shared-library component rendered white in a dark dialog.** Cloned fields next to them were dark.
   Cause: the library main component carries an explicit Semantic mode, and a fresh instance copies it, so it ignores the frame's mode. Clones of existing instances do not have it. Rule: after `importComponentByKeyAsync(...).createInstance()`, clear `explicitVariableModes` on the new instance (`clearExplicitVariableModeForCollection`) unless the design wants that mode. Check: screenshot right after the first created instance; compare its fill with a cloned sibling.
2. **A failed clone left a stray node on the page.** `node.clone()` of a node from another page lands on the current page; the script failed before `insertChild`, so the copy stayed at (0,0). Rule: after any failed write script that clones, list the page's top-level children and remove only the copies that script made.

## Heavy audit reads froze a Figma tab (2026-10-20)
1. **A ds-auditor read froze a large Code to Design screens file.** A screens audit ran `findAll` over whole screen frames with a nested `findAll` per text node; FigCli timed out at 100 s, the script kept running inside Figma and every later eval on that file failed (even `1+1`) until the tab was reopened. A write script queued behind it also timed out.
   Cause: quadratic traversal on big screen pages, plus the timed-out eval still running (see the background-tab lesson). Rule: audit reads walk one page at a time, never nest `findAll` inside a per-node loop (walk up `parent` instead), and process instances in chunks of about 20 per eval. Check: time one chunk first; if it takes over 30 s, split further before looping.

## Checkpoint approvals (contributed by EmG38, 2026-10-20)
1. **Foundation and Components were built with no confirmation between tables/components.** A session built all 6 Primitive color ramps, Semantic, Spacing, Radius, Size and Typography collections from a single bundled "merge approval" question (which only covered near-duplicate values, not the actual proposed ramps), then built 12 components (Button, Icon Button, Divider, Checkbox, Radio, Toggle, Badge, Avatar, Tooltip, Tabs/Item, Pagination/Item, Breadcrumb/Item) back-to-back with zero approvals between them.
   Cause: the skill only defined 3 end-of-phase checkpoints (Foundation, Components, Screens); nothing required a stop-and-ask before each individual ramp/table or each individual component inside those phases, so the agent kept going once the phase started. Rule: "Per-table and per-component confirmation" — before writing any Primitive ramp/token table, or building any component, show it and get an Ask (choice) approval first; one table or one component per question, never batched. Check: before a Foundation or Components script runs, there must be a preceding approved Ask (choice) naming that exact ramp/table/component in the transcript. Fixed in `memory/decisions.md` (Entry flow), `Design_System_Intake_Skill/SKILL.md` section 8, `Web_Design_System_Skill/SKILL.md` section 2, `Design_System_Intake_Skill/steps/brownfield-1-screens.md` step 5.

## Dashboard select lists in dark mode (2026-10-15)
1. **The Tool and Model lists could not be read (Abdul).** In dark mode the open lists under the message box showed light grey text on a white list.
   Cause: the select was transparent (`background:none`) with the theme's light text; Windows draws an open native list with the select's background, so it fell back to white while the options kept the light text. Headless screenshots never show an open native list, so the check missed it. Rule: every `select option` gets the theme's background and text color explicitly. Check: read the computed `color` and `background-color` of an `option` in Dark mode (both must come from the theme), not only a screenshot.

## Dashboard terminal buttons on Windows (2026-10-15)
1. **Sign in opened an empty terminal (Abdul).** Settings → Gemini CLI → Sign in showed "The filename, directory name, or volume label syntax is incorrect" and never started `gemini`; every button that opens a terminal (Sign in, Open, Continue with another tool, phone, Open in Claude Code) had the same bug.
   Cause: `runInTerminal` passed `cd /d "<Root>" && <cmd>` as a spawn argument; Node escapes its quotes as `\"`, which cmd.exe does not understand, so the `cd` failed and `&&` skipped the tool. The tests only checked the command strings, never a launched window. Rule: on Windows, start the window with one verbatim command line (`cmd /d /s /c "start "" cmd.exe /k <cmd>"`, `windowsVerbatimArguments`) and the Root as `cwd`, so no `cd` is needed. Check: launch one terminal button for real (a script that writes `cd` and its quoted argument to a file) before calling the change done.

## Cleaning up scratch output (2026-10-14)
1. **A shared output folder was deleted with older files in it.** After moving its own screenshots out of `.playwright-mcp/` (Playwright MCP's output folder in the Root), Claude removed the whole folder, which also held screenshots, logs and two scripts from earlier sessions.
   Cause: the folder was treated as this session's own because this session had just written to it; it was not listed before the delete. Rule: never delete a folder Claude did not create in the same session; move or delete only the files it created, by name, and remove a folder only when it is empty. Check: list the folder right before any delete and compare it with the files this session wrote.

## Storybook docs with snake_case token names (2026-10-13)
1. **Docs pages were unreadable in Dark (Abdul).** On the Music App Storybook every docs page showed dark text on a dark page.
   Cause: `templates/docs/DocBlocks.tsx` picks the docs text, muted, surface and border colors by token name with hyphen patterns (`on-surface`, `outline-variant`); this DS uses md.sys names with underscores (`on_surface`, `outline_variant`), so nothing matched and the fixed light fallbacks were used. Rule: the name patterns accept `-` and `_`. Check: `templates/mode_check.js` on every docs page in every mode (`unreadableCount` 0) before a Storybook is called done, which this build skipped (lesson 5 of the pilot). Also: `storybook/figma-links.json` (node ids per component) is part of every build, or the Docs pages have no "Open in Figma" button.

## Size tokens bound on resizable components (2026-10-13)
1. **The Play button turned into a pill (Abdul).** After `md/sys/size/touch_target` (48) was bound to the height of every Icon Button and Button variant, the Play button in Playback Controls (resized to 64 x 64) became 64 x 48, the Mini Player Play (40 x 40) became 40 x 48, and the Section Header More button grew from 36 to 48.
   Cause: a variable bound to a main component's height wins over the height of every resized instance, so each instance that had been scaled kept its width and snapped to the bound height. The binding script only checked that the main component's height matched the token. Rule: bind Size tokens only on components that are never resized as instances (or bind width and height together on the instances that use another size); before binding, list every instance (DS file and Design files) whose size differs from its main component, and skip the binding when any exist. Check: after a Size binding, compare instance sizes before and after (any instance whose height changed is a regression). Fixed: height unbound on Button and Icon Button; Play 64 x 64, Mini Player Play 40 x 40 and More 36 restored.

## Reorganizing screens in a Design file (2026-10-13)
1. **Dark screens turned Light after the file was reorganized.** Moving the Dark and Light screen frames out of their old sections into one section per screen dropped the Dark look.
   Cause: the Light/Dark mode was pinned on the old SECTION (`explicitVariableModes`), not on the frames; a frame takes its mode from its parent, so moving it changed its colors without any error. Rule: before moving screens, read `explicitVariableModes` up the parent chain; after moving, pin the Semantic mode on every screen frame itself (`setExplicitVariableModeForCollection`, frames named `... / Dark` or `... / Light`). Check: read the frame fill color after the move (Dark frames must resolve to the dark surface), and the screens audit lists frames whose mode is not pinned on the frame.

## FigCli Yolo writes in a background tab (2026-10-13)
1. **A docs-page build hung and left duplicates.** Building ➜ Color through FigCli `eval` stopped after a few nodes; the CLI timed out, retried on its sync path, and the stalled scripts kept adding nodes about every 30 s.
   Cause: the DS file was not the visible Figma tab (`document.visibilityState` = `hidden`), so every async Plugin API call (`setTextStyleIdAsync`, `loadFontAsync`) was throttled to about 30 s. Reads and sync calls stay fast, which hides it. A timed-out `eval` keeps running inside Figma. Rule: before any write batch with async calls, check `document.visibilityState` with the same `FIGMA_FILE`; `hidden` -> bring the tab back with `node tools/figma_focus.cjs "<FIGMA_FILE>"` (since 2026-11-03 the `figma_focus` pre-tool hook does it before FigCli writes and screenshots) and ask the user only when it still reads `hidden` (figma-files.md step 8); write nothing until it reads `visible`. After a timeout, remove the half-built container so the stalled script fails on its next write, then rebuild. Check: one `eval "document.visibilityState"` before the first write of each batch.

## Audits with FigCli Yolo (2026-10-11)
1. **ds-auditor could not run on a FigCli Yolo machine.** It had only Desktop Bridge tools and no Bash, and stopped when the Bridge was not connected, although Yolo is the main tool and the Bridge is used only for slots.
   Cause: the agents were written before Yolo became the default (2026-10-05) and were never updated. Rule: every agent that reads Figma uses the tool saved for the file, through FigCli read commands or the Bridge; FigCli `check` alone is never the audit (one sample variant per set). Check: `guard_figma.cjs` denies non-read FigCli commands in read-only agents; `tools/figma_styles.figma.js` passes the read-only check (plain-object fields written as `out['x']` so they do not look like node writes). Fixed in `.claude/agents/*.md`, `.claude/hooks/guard_figma.cjs`, `.claude/settings.json`.

## Hooks on a new machine (2026-10-07)
3. **Node.js still had to be installed by hand.** The setup check runs on Node.js, so a machine without it got no offer at all; Abdul wants a non-technical user to install nothing by hand.
   Rule: `Setup-Windows.cmd` / `Setup-Mac.command` in the Root install every item of `tools/dependencies.json` with one double-click (winget / Homebrew; download pages when winget is missing). Inside Claude, a session start with no hook context means the hooks did not run: Claude checks `node --version` and installs Node.js itself after the yes (CLAUDE.md > Always start here, `steps/machine-setup.md`). Check: run `tools/setup_windows.ps1` with a tool missing: it is installed or its page opens; a new dependency needs only a `dependencies.json` entry on Windows, and the same line in `Setup-Mac.command`.
2. **Dependencies were found one by one, by failing.** Python was only discovered missing when a hook broke; nothing listed what a new machine needs or checked it, and Abdul did not want a check costing time every session.
   Rule: one list, `tools/dependencies.json` (Node.js, Python 3, Git, Figma Desktop, with per-OS install commands). The SessionStart hook `setup_check.cjs` checks it, records success once per machine in `.claude/.state/machine-setup.json` and skips the checks after that; anything missing -> `Design_System_Intake_Skill/steps/machine-setup.md` offers one "Set up now" menu, installs after the yes, then a restart. Hook commands use `node -e ... run.cjs <hook>` (no `$CLAUDE_PROJECT_DIR` shell syntax), because Claude Code on Windows runs hooks in PowerShell when Git is missing. Check: `node .claude/hooks/run.cjs setup_check --report`; a new tool the workflow needs goes into `dependencies.json`, never only into a skill.
1. **"Stop hook error: Python was not found" on a colleague's first run (Windows).** Every hook in `.claude/settings.json` ran `python ...`; on Windows without Python, `python` is the Microsoft Store alias, which only prints an install message and fails, so every Stop, Edit and Figma call showed a hook error.
   Cause: the hooks assumed Python, which is not part of the setup that Claude Code itself needs. Rule: hooks are written in Node.js (`.claude/hooks/*.cjs`, run with `node`), because Node.js 18+ is already required (Setup step 1, FigCli, Storybook). A hook never fails because an optional tool is missing: one that needs Python (the daily Storybook check via `tools/project_status.py`) tries `py -3`, `python3`, `python`, and without one skips that part and tells Claude to run intake 0b check 0, which offers to install Python 3 (winget / Homebrew, only after the user's yes, then a Claude Code restart) because Abdul wants new users set up for them, not left to struggle. Check: every `"command"` in `.claude/settings.json` starts with `node`; run each hook with `{}` on stdin on a machine without Python: exit 0, no error. Fixed in `.claude/hooks/`, `.claude/settings.json`, `README.md` (Setup), `Design_System_Intake_Skill/SKILL.md` (0b check 0).

## Figma comments (2026-10-06)
1. **Comments could not be read (401 Invalid token).** `figma_get_comments` failed on a DS file even after the token was replaced.
   Cause: comments come only from the Figma REST API (FigCli Yolo and the Plugin API cannot read them), and figma-console reads `FIGMA_ACCESS_TOKEN` only when Claude Code starts. Rule: the token needs `file_comments:read`; after changing it, quit Claude Code fully and start a new session; the user edits the token, Claude never reads or writes it. Check: one `figma_get_comments` call before planning comment work; 401 -> stop and ask for a new token. Fixed in `Design_System_Intake_Skill/steps/figma-comments.md` (14.1).

## Tool install steps (2026-10-06)
1. **Material 3 skill installer failed on Windows.** The command given was `powershell -ExecutionPolicy Bypass -File .\install.ps1 -Agent claude,codex,antigravity`; PowerShell rejected `-Agent`.
   Cause: with `-File`, a comma list reaches the script as one string, not an array, so the `ValidateSet` check fails. Rule: Windows install steps run the script in the open PowerShell window after `Set-ExecutionPolicy -Scope Process Bypass -Force;` (process only), never through `powershell -File` with list arguments. Check: before giving a PowerShell install command, read the script's `param()` block; any `[string[]]` parameter means no `-File`. Fixed in `Android_Design_System_Skill/SKILL.md` section 11.

   Cause: the Figma descriptions used "Usage Rules:" and the parser only knew "Usage rules:"; the pilot had no registry `docs` block. ## 2026-10-07 — Financials source charts and Yolo audits (Codex)
- Figma instances reject vector path geometry changes. Build source geometry as editable mark masters in the authorized library page and nest their instances in chart organisms; split source mark sets below 30 variants. Never detach or flatten the screen.
- A variable paint with a black fallback may render black when rebinding the same alias on an instance. `DS.paint(name, consumer)` must resolve the current consumer mode and supply the resolved RGB fallback while retaining the alias. Check Light and Dark screenshots.
- FigCli Yolo truncates eval output at 20,000 characters and appends non-JSON text. Return compact audit counts/registry or chunk results. Validate saved JSON before using it as evidence; truncated files are not audit reports.
- Changing a shared BOOLEAN property reference on one variant can change its shared default. Set the intended set default explicitly, then override Show Icon on screen/sample instances. Visually check both Card and Strip.

## Financials fidelity repairs — Codex, 2026-10-07
- Reuse existing Badge variants without paint overrides. Reset overrides before swapping the main component; resetting after swap restores the former main. Verify visible text and translucent fills in screenshots.
- Load only required font family/styles and cache loaded fonts; loading all available Poppins variants can timeout and trigger duplicate CLI retries.
- Set nested label text to HUG/auto width before composing a compact switcher. Check native-scale screenshots as well as geometry bounds.
- Snapshot component variant names before adding a new axis; variantProperties can fail while siblings are temporarily inconsistent.
- The screen checker must ignore invisible placeholder text and accept the genuine Filter label in known filter controls; all other visible placeholders remain findings.
